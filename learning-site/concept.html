概念 · A 论文

Exploring Super-agent Design

当瓶颈从「模型会不会」变成「人盯不盯得住」，Agent 就不再是一个更长的会话，而是一套能派活、能记住、能自愈的组织。

  • 4 个特征 + 5 个模块
  • WU-3 正文

先记住一句话

A 论文的钥匙：它不提出新理论，而是把计算机系统里的经典思想搬进 Agent 系统——调度器、进程隔离、发布–订阅、缓存、快慢路径、推测执行、存算分离、看门狗。记住这条，下面五个模块都会变得顺理成章。

四个特征

论文先定义目标，再倒推架构。四个特征不是愿望清单，而是五个模块的需求来源。

01

连续Continuous

你在飞书、GitHub 这些本来就在的地方直接说话，换渠道也不用复述背景——它始终是同一个 Agent。

反面：每个渠道一个孤立会话，用户自己复述背景。

主要由：Router 层 + 全局记忆

02

产出Productive

它响应快，能并行推进多个复杂任务；上一条命令还没跑完，你也能接着下新指令。

反面：一个长任务卡住整个对话，用户只能等。

主要由：Worker 并发 + 全双工

03

主动Proactive

它监听群消息、PR、CI 这些环境事件，该处理就处理，不该说话时保持安静。

反面：只有被 @ 才动，否则永远沉默。

主要由：Trigger + 两级过滤 + 推测执行

04

持久Persistent

它一直在线上，长跑中能从异常恢复；设备可以睡、可以换，任务不断线。

反面：合盖就停，换台设备就失忆。

主要由：计算 / 状态 / 环境分离 + Watchdog

五个模块

模块不是五个功能点，而是对四个特征的五种回答。下图是它们的位置关系，下面逐条给一句人话解释。

01

双层架构：Router + Worker

Router 只负责跟人打交道、记全局、派活；Worker 在隔离上下文里只干一件事，干完向 Router 汇报。

支撑：连续、产出。Router 不执行任务是结构保证，不是 prompt 祈祷。

02

事件驱动：Trigger 的四道关

把「人打字」换成环境事件，再用四道关决定看不看、送给谁、带什么上下文、什么时候先做。

支撑：主动、连续。稳定的判断下沉成代码，模糊的判断留给模型。

03

面向人的交互：全双工与多通道

前台对话和后台任务解耦，长任务跑着也能插话；不同渠道用不同的说话方式，IM 尤其克制。

支撑：产出、连续。异步 ReAct 让 start() 立刻返回，结果作为新事件回到会话。

04

计算、状态、环境分离

跑 Agent 的计算可以随时重启，会话状态放数据库，代码和环境留在你自己的机器上按需连接。

支撑：持久。计算与状态分离，计算与执行环境分离，环境按需连接而不是搬上云。

05

Watchdog：主系统之外的独立控制环

主系统之外再放一个有工具的 Agent，定时检查基础设施和任务是否真的在推进，跑偏就修。

支撑：持久。它同时是监控者和运维接口，可以用自然语言问「刚才为什么失败」。

它们怎么咬合

四个特征定目标，五个模块给结构。关键不是「有几个 Agent」，而是三条结构性约束：Router 不执行任务、Worker 上下文隔离、事件按 Thread 路由。

所以论文的结论不是「换个更强的模型」，而是「把会话变成实现细节」：用户看到的是连续的交互，系统内部才是一次次隔离的执行。
