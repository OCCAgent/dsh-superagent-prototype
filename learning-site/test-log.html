第一层 · Harness 自改进实测

轨迹来源是阶段 2 的真实运行记录（trigger / PR / worker 状态）。共 5 条行为边界：3 条弱点、2 条优点。

编号实测发现类型提案采纳状态
F1 判定为「重复/无新工作」的消息不会得到群内回执，用户容易误以为被无视。 弱点 任务模板加「如判定无需新工作，请回复原因」；dropped 必回执。 未采纳
F2 PR 合并会终止当前 worker assignment，连续派发时后一单元可能被丢弃。 弱点 PR 合并不立即结束 assignment；丢失单元自动重投。 未采纳
F3 不 @ 的消息也会入库 trigger，过滤实际发生在 disposition/Eval 层，与 A2 判据描述不符。 弱点 修正 A2 判据；增加 mention-only 过滤。 部分采纳
F4 Worker 能核实 git 历史与 PR 状态，识别重复请求并拒绝无效工作。 优点 沉淀为使用姿势：任务里写明「已完成的不要重做」。 已采纳
F5 同一 Thread 的后续消息会追加进同一工单，不碎片化建单，插话能并入当前任务。 优点 沉淀为使用姿势：同一项目的多个 WU 在同一话题下连续下发。 已采纳

采纳口径：代码级采纳 0 条；判据修正 1 条（F3）；行为规范 2 条（F4/F5）；未落地 2 条（F1/F2）。为什么零代码级采纳：本轮目标是完成学习网站，规则/机制改动属于阶段 3 剧本 B；按方案 E1-6，「无一采纳 + 原因分析」是合法结果，伪造采纳率是红线。

数据说明：阶段 1 Harness 基线没有单独跑脚本实验；本页的可复用轨迹来自阶段 2 的真实运行记录，与仓库中的《阶段2实测发现与学习素材》一致。F1/F2 的修复验证留待阶段 3。

第二层 · 四特征逐项验证

每个特征至少 2 个用例（典型 + 扰动）；连续性和主动性各加 1 个“不应发生”的负向用例。退出判据：至少 3/4 成立，失败项必须归因到架构层或实现层。

用例类型场景结果
C1 连续典型工单 PR 评论追加需求，不引用原飞书消息通过 归到同一工单
C2 连续扰动群 B 无关闲聊后，群 A 原 Thread 追加通过 1/1 归属
C3 连续负向群 B 的无关闲聊通过 0 泄漏
C4 连续规范指定群 A 发起；群 B 追加需求、无显式引用不成立 0/1，候选无关联工单
P1 高效典型1 个 worker 槽位下连发 5 个独立任务通过 4 排队、1 运行
P2 高效扰动队列满时运行中工单收到人的插话通过 立即送达
A1 主动典型 · observeCI 失败 + 规则授权，无 @记录 候选 + would-accept，0 工单
A2 主动典型 · auto同一环境切 auto，重复 CI 失败通过 inferred 建单
A3 主动负向 · observe中性讨论、未 @、无匹配规则通过 0 误触发
A4 主动负向 · auto同上，auto 模式通过 0 误触发
A5 主动扰动同一规则下 CI 成功通过 0 建单
D1 持久典型worker 执行中宿主停止并重启通过 目录/Session 保留，recovery note 继续
D2 持久扰动派工后未回报时重启，另有排队工单通过 2/2 保留、仅 1 运行

架构层归因（连续 C4）：实现只用三种结构关系建立归属——发起 Thread、工单跟随的 PR Thread、同一 Trigger 同属多个 Thread。Correlation 只补上下文、不路由；attach 要求消息显式指向工单。因此 C4“无显式引用的跨渠道追加”不是模型偶然失败，而是当前架构没有这条路径。按第三层入口判据，“群聊追加要求关联到现有 Ticket”这一条当前不满足，先不应启动第三层端到端测试。

连续深挖：Ticket 才是持久实体。PR 合并、工单结束后，人在 PR 评论追加要求可恢复同一工单（Mandate 不变）；删掉 worker Session 后重启，Ticket/目录/progress 报告保留、Session 重建；两个工单的跟进 0 串任务。边界：CI 不能唤醒结束工单；群 B 更新只有在 router 显式 attach 时才进入群 A 工单，跨群/跨端自动归属不存在。七层分析见仓库 experiments/four-features/continuity-deep-dive.md。

Token 成本（与延迟同等重要）：learning-site 6 个 WU 共 52,284,551 total tokens，其中 cache read 51,922,304（99.3%），约 8.71M / WU。第三层暂定 cap = 3 × 基线 ≈ 26.1M total tokens / 工作单元；未收敛即超预算时转人工复核，不自动重试。

数据说明：机制基线是可复现的 Runtime 级实验（fake DSH host、脚本化 Router/worker 步骤），只验证协调机制；真实运行数据为单部署、小样本观测，不足以宣称正式 p50/p95。完整用例、指标、token 表与现场协议见仓库 experiments/four-features/README.md。
