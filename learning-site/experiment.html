阶段 1 · Harness 基线

原计划用固定终端任务集跑「轨迹 → 弱点 → 提案 → 回归采纳」。本轮没有单独跑脚本实验；可复用的轨迹来自阶段 2 的真实运行。

发现类型提案采纳状态
F1 判定重复/无新工作后无群内回执弱点dropped 必回执；任务模板加说明未采纳
F2 PR 合并终止 assignment，连续派发有丢单风险弱点合并不立即结束；丢失单元自动重投未采纳
F3 不 @ 也入库 trigger，过滤在下一层弱点修正 A2 判据；mention-only 过滤部分采纳
F4 Worker 识别重复、拒绝无效工作优点沉淀为使用姿势已采纳
F5 同 Thread 插话直通，不碎片化建单优点沉淀为使用姿势已采纳

结论：代码级采纳 0 条；判据修正 1 条、行为规范 2 条。按方案 E1-6，「无一采纳 + 原因分析」是合法结果，伪造采纳率是红线；F1/F2 的修复验证留待阶段 3 剧本 B。

第二层 · 四特征验证

每个特征至少 2 个用例（典型 + 扰动），连续与主动各加 1 个负向用例；退出判据是至少 3/4 成立，失败必须归因。

特征结果关键证据
连续 Continuity不成立（部分）同 Thread / PR Thread 追加可归属；无结构关联的跨群追加不会自动归属（C4，架构层：Correlation 只补上下文、不路由）
高效 Productivity成立1 槽位下 5 个任务立即接单并排队；运行中插话不被阻塞；0 串扰
主动 Proactivity成立CI 失败在规则授权下无 @ 建单；中性讨论 0 误触发；CI 成功 0 建单
持久 Persistence成立worker 中断与派工未回收均可恢复；0 人工步骤、0 重复工单

Token 成本：learning-site 6 个 WU 共 52,284,551 total tokens，其中 cache read 51,922,304（99.3%），约 8.71M / WU。这是真实运行的观测值，不是基准；样本小，不能据此宣称 p50/p95。

证据边界

能证明：这套调度与路由机制能在真实飞书/GitHub 环境里跑通多 WU 交付；四个特征中有三个在本环境成立；发布链路可用。

不能证明：真实研发效率提升、代码质量提升、跨团队泛化。A 论文的实验是合成负载（约 300 条消息、约 20 个工作请求、耗时工具模拟编码、每配置 5 次）；本轮四特征验证是单部署、小样本观测，不是受控实验。所有数字只作为本环境的第一份可复现基线。

连续性缺口：3/4 不等于「差不多」；C4 失败有明确架构归因，修复需要新增「按语义匹配并 attach」或要求来源提供业务键，属于后续架构变更，不在本轮发布范围内。
