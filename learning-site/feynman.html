先看 2×2 地图

把「单 Agent / 多任务系统」和「固定 harness / 自进化 harness」交叉，地图就很清楚。

Super-agent Exploring Super-agent Design把工装做成组织 空位让整个组织自己进化工装

右下角是两篇拼起来最值得想的下一步：把 Self-Harness 的「证据 → 提议 → 回归」循环，从单个模型扩展到整个 Super-agent 系统。难点也很清楚——证据单位从单条轨迹变成跨 Thread/Worker 的事件流，回归集要从基准扩展到历史回放与 held-out 团队，准入要灰度、归因、可回滚，还要决定谁批准。

两篇论文对照表

按设计动机、核心机制、验证方式、局限四个维度并排看。

维度A · Exploring Super-agent DesignB · Self-Harness
设计动机 单会话 ReAct 的瓶颈从模型能力转向人的注意力：Agent 要常在线、能并行、能主动、跨渠道连续。 手工为每个模型调 harness 不可扩展；Meta-Harness 贵、未必有更强模型、失败模式还容易错配。
核心机制 双层架构（Router/Worker）、Trigger 四道关、全双工与多通道、计算/状态/环境分离、Watchdog；把计算机系统思想搬进 Agent。 失败签名聚类 → 多样最小提案 → held-in/held-out 双边回归；只改声明式可编辑面，留下可审计版本链。
验证方式 合成负载（约 300 条群聊/CI 消息，约 20 个工作请求）、耗时工具模拟编码、每配置 5 次；Router 批处理压测 1→40 条/分钟。 单基准 64 题、3 个模型、每候选重复 2 次；用 held-in 看是否解决动机证据，用 held-out 看是否弄坏别的。
局限 合成负载、简化环境、非真实编码；只验证调度与路由，不能推出真实研发效率或代码质量提升。 单基准、重复次数少、只能有界修改；依赖评估器质量，跨基准/跨团队泛化未验证。

怎么读：A 回答「组织怎么搭」，B 回答「工装怎么改」。两篇共用同一个 harness 概念，但一个把它做成身体，一个给它装上变异与选择机制。

十个苏格拉底式自测题

先自己答，再点开对照。答案按底稿整理，不追求标准表述，追求讲得通。

Q1 为什么「每个事件开一个新会话」不是 Super-agent？

它只解决了并发，没有解决连续性。任务相关时会缺全局上下文；多个会话分别回复用户，交互也会混乱。Super-agent 要「连续 + 产出」同时成立，所以需要 Router 维持全局、Worker 隔离执行的两层结构。

Q2 Router 不执行任务，为什么不会成为瓶颈？

它只做轻量交互和派发；一个推理 turn 内到达的 Trigger 排队，下一个 turn 合并成一次调用，prefill 并行，所以请求耗时随批量增长很慢。压测里到达率 1→40 条/分钟，摊销到每个决策的时间反而从 6.4s 降到 1.6s。上限是上下文长度和单 turn 可准确处理的 Trigger 数。

Q3 Fast Path / Slow Path 分别指什么？为什么这样分？

Fast Path 是确定性的程序化策略（来源、群、白名单、三种响应模式），低成本挡掉大多数噪音；Slow Path 是大模型结合上下文和 prompt 策略做语义判断。把稳定的判断下沉成代码、把模糊的判断留给模型，才能同时控成本和延迟。

Q4 订阅透传解决了什么？没解决什么？

解决了「同一 Thread 的后续事件不必每次都经过 Router」，省下 Router 的决策次数和 token（实验里约 −30% 决策、−37% token）。它不解决任务本身的正确性，也不替代跨任务协调——那仍由 Router 负责。

Q5 Inline & Spill 与 Chain of Recall 是什么关系？

Inline & Spill 是「单个对象怎么放进/放出窗口」的微观操作；Chain of Recall 把同一原则应用到对象图上，让模型顺着 ID 引用一跳一跳找回多跳之前的上下文。前者是缓存策略，后者是基于缓存的检索路径。

Q6 计算/状态/环境分离的两级各解决什么？

第一级把无状态计算放进弹性容器、状态放进数据库，解决「设备一睡 Agent 就停」；第二级把执行环境留在本地、只装无状态 daemon，解决「环境搬不动/搬不全」。两级合起来让 Agent 既常在线，又能连到真实机器。

Q7 Watchdog 与普通监控的区别？

普通监控看进程、端口、错误率；Watchdog 还用一个独立的 Agent Session 判断「任务有没有实质进展、有没有跑偏」，并且能用自然语言被询问、能在运行时调整主系统。它监控的是「干活这件事本身」。

Q8 Self-Harness 与 Meta-Harness 的区别？

Meta-Harness 用更强的外部 Agent 去改弱模型的 harness；Self-Harness 让被评估的同一个固定模型，在当前 harness 下提出对自己的有界修改。前者是外部搜索，后者是把改进闭环内化，避免外部模型的成本与失败模式错配。

Q9 为什么接受规则要求 held-in 和 held-out 都不降？

held-in 检验「是否真的解决了 motivating evidence」，held-out 检验「有没有为了修这个而弄坏别的」。只看总分会让「拆东墙补西墙」的过拟合改动混进来；双边不降是一种保守的回归门。

Q10 两篇拼起来，最自然的下一步是什么？

把 Self-Harness 的三步循环用到 Super-agent 的系统 harness 上：用跨任务执行轨迹挖协调、上下文、路由层面的失败模式，提有界改动，在历史回放和 held-out 团队上做回归，再灰度上线。关键难点是证据单位、回归集、准入规则和「谁批准」。
